# 数据来源与版本范围

## P0 事实底本

人物、关系、引语、章节摘要与结局等事实层内容，以 **甲戌本**、**庚辰本** 为唯一底本。

- 甲戌本、庚辰本中可定位的材料，可以进入事实层。
- 两本之间存在异文，或只见于其中一本的内容，必须写明版本、回目、定位及差异状态。
- 第八十一回及以后、程高系统及其他续书材料不得作为事实层的来源。若将来需要展示版本比较，必须放入明确标注的比较字段，不能覆盖底本事实。

本项目不以本文件替代版本校勘。每次新增或改写人物事实，都应同时保存可复核的版本、回目、原文定位；影印本或可靠校勘本页码优先于网页文字版。

## 数据结构

`data/provenance.json` 是机器可读的来源总表，包含：

- `policy`：底本范围和前台展示规则；
- `sourceCatalog`：可引用的版本载体；
- `evidence`：已核实事实与其回目定位；
- `auditQueue`：待核历史数据，不能视作已完成校勘。

人物记录可使用下列来源字段：

```json
{
  "sourceRefs": [
    {
      "sourceId": "jiaxu-wikisource",
      "edition": "甲戌本",
      "chapter": 3,
      "locator": "第三回末段“母舅王子腾”",
      "claim": "王子腾为薛蟠之母舅"
    }
  ],
  "quoteSources": [],
  "outcomeSources": []
}
```

`quoteSources` 与 `quotes` 按下标一一对应；`outcomeSources` 至少应有一条有效来源。来源只能引用 `sourceCatalog` 已登记的甲戌本或庚辰本，章节必须在第 1–80 回，且必须提供 `locator`。

## 展示准则

- 无完整 `quoteSources` 的 `quotes` 是待核摘录，前端不显示为“经典语录”。
- 无 `outcomeSources` 的 `outcome` 是待核信息，人物名录不显示为“结局”。
- `sourceNote` 只可解释已登记的版本状态，不能替代逐条来源。

## 校验

在仓库根目录运行：

```bash
npm run validate:data
```

该命令会阻断重复人物 ID、悬空关系／亲属／知识关联、无效关系类型、超出底本范围的来源和来源目录不一致等错误。历史待核数量会以警告显示，并与 `auditQueue` 对照，供后续校勘逐批清理。
